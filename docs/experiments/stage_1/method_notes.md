# Stage 1 方法与审计说明

本文记录实现与解释边界；最终结论依赖完整矩阵，不能从部分完成结果推断。

## 固定对象与比较

所有生成使用原始 PocketXMol teacher checkpoint，不训练、不修改参数。口袋 ID、20/80 开发/确认拆分、五个种子和阈值见 protocol.json。该拆分用于避免本轮选参泄漏，不声明这些口袋对历史模型完全未见。

独立候选以 seed+r 生成；N1/2/4/8 使用同一原始候选池的嵌套前缀。尾部 r4..7 与首部合并只建立原始 SDF 链接，保留来源与校验。失败候选纳入计划分母，不补采。原生精修可能提前退出，比较报告实际 graph NFE，不能仅凭名义预算声明完全相等。

P_phys 同时要求可清洗、单片段、五项几何、口袋碰撞检查及能量检查通过；P_joint 还要求原始构象 score-only Vina ≤−7。−6/−8 为敏感性分析。能量为 PoseBusters 50 构象、ratio≤100、seed42，线程1；不用于普通置信度/几何排序。Vina 不重新嵌入或优化候选构象，受体准备与打分计时分别记录。

## 适配方法

FK 为单口袋 P4/P8 完整图粒子。根据清洁预测的键长、非键接近与口袋接近软惩罚作差分势重采样，interval20/50、strength2/5；不调用能量或 Vina。复制完整粒子图及元数据，保留权重、ESS 和祖先数。最终槽位允许复制，重复与多样性计入分析；P8 以不超过4图的模型调用分块执行。

局部修复先生成100步，然后每轮选择 ceil(0.25*n) 个原子，随机或最低位置置信度。未选原子的类型/坐标、未选内部边及固定距离均按 teacher maskfill 训练协议固定；所选原子所有关联边自由。每步断言固定状态与口袋不变。noise_start=1，每轮100步，不通过结果反复调噪声。

早期 partial version1 漏设 fixed_halfdist，虽固定状态断言通过，却不满足 teacher 条件元数据协议。其结果保留作诊断，不用于选参/主比较。version2 与 teacher set_fixed 的四种标志逐项一致，重新生成缺失的开发单元；修复 ledger 覆盖旧同名单元。确认集必须冻结 version2 实现。

## 恢复和可重复性

原始重构芳香环修复吞掉超时异常，现明确传播 TimeoutException，恢复已有300秒上限。旧中断目录保留并标为 abandoned；完整重试使用新目录，不从旧结果挑选候选。相同 seed 重试未得到逐字节一致输出，原因未被严格隔离；不宣称 GPU 位级确定性或跨方法共享噪声。

缓存必须匹配 SDF、checkpoint、配置和线程协议。早期能量线程0结果保留但正式评估使用线程1；独立重算检查与日志见 smoke。诊断状态在独立目录评分，不进入主分母。

## 统计、成本与解释

先在口袋内平均种子，再按口袋做至少5000次 cluster bootstrap；差值按相同口袋/种子配对。开发20、确认80、全100分别呈现。最终选择一项 FK 和一项 partial，开发矩阵全部评估后冻结；确认结果及后续补齐的开发种子不参与调参。

generation 时间包含数据流、重构与写入；startup/import、模型设置、warmup 及受体准备单列。实际 NFE hook 将预热与正式调用分开。重复计时固定8个确认口袋、batch4、同一 A10040GB GPU、3轮，不解释为单请求服务延迟。

原生 sampler 默认记录未使用的完整 CPU 轨迹，FK 与局部循环的记录开销不同。额外 timing_trace_control 将所有适用方法的完整轨迹记录关闭，仍保留置信度历史；CPU 回归证明标准与 AR 采样的状态、预测、置信度、NFE、RNG 不变。成本优势须同时检查统一记录对照，不能只用原始比值。

stage_2 推荐必须审计确认集的两个主指标、实际 NFE/筛选成本、validity/complete、coverage、大小和多样性。没有收益也交付负结果；不继续调参或扩张 backbone。

## 保存状态的逐原子归因

`tables/repair_state_attribution_v2.csv` 对相邻轮次逐原子比较，历史全局索引转换为图内编号；两侧 SDF 的原子数必须等于原始图，才认可顺序映射。96 个保存状态对比均通过。未选原子类型、坐标及未选内部键的连接关系保持不变；SDF 序列化坐标差为0。

键级需区分原始图、未清洗 SDF 和芳香性标准化后的化学图。87 个可清洗对比中，芳香性标准化后仍有40处未选内部键级/芳香性变化；未选内部连接增删为0。该结果不能归因于采样器直接更新固定边：原始模型图每步有精确断言；重构和全环芳香性变化会影响最终键表示。正式物理评估基于最终 SDF，因此不宣称最终化学键级始终保持精确固定。不可清洗的9个对比保留错误及未标准化变化，不丢弃。

置信度可靠性表的 sigmoid 仅为 raw teacher 位置置信度的单调显示变换，分箱为预设10个等宽区间，不代表校准后的成功概率。表中经验通过率按正式候选加权，跨运行汇总；它是诊断而非拟合的部署校准模型，不能据此将 raw 置信度数值解释为 P_phys/P_joint 的概率。

后续能量评分同时保留 PoseBusters energy_ratio 模块的具体 warning（例如未能生成全部50个构象）。这是错误归因字段，不修改构象数、阈值、随机种子或线程数。早期缓存记录可能没有该字段，其通用缺失原因和原始 energy.log 保留；不能将缺失警告字段视为没有发生警告。

### 完整候选池评估恢复与并行补齐

核心 40 项生成已完成。根目录评估 watcher 曾把 `timing/DONE` 的汇总完成标记当作候选任务，因该目录没有 `run.json` 而退出；修正为仅评估带 `run.json` 的候选目录后恢复。显式指定缺少元数据的候选目录仍报错。现有候选不重新生成，未完成评估继续按原阈值和缓存协议执行。

冻结配置的开发集补充任务在 GPU39 的空闲 GPU1 上运行，确认任务继续使用 GPU2。补充 driver 使用独占文件锁；确认队列随后进入同一补充 driver 时等待锁释放，再读取最新 ledger 并跳过已完成任务，避免重复生成。并行执行不改变冻结配置、开发/确认划分或选择规则。

全部 12 个方法/预算单元的记录开关比较已覆盖每单元三轮，共 36 对计时。`tables/trace_materialization_comparison*.csv` 保留两侧实际 NFE；由于 GPU 非确定性、化学重建与原生 refinement 早停，开关比值不作为纯粹的轨迹记录因果开销估计。

### Scaffold 计数口径

Murcko scaffold 的空字符串对应没有环骨架的完整分子；CSV 读取后为空值。`unique_scaffolds_complete` 和候选池 `scaffold_count` 计数非空环骨架，不能把它们解释为包含无环分子的全部骨架类别数。正式预算汇总另报告 `acyclic_fraction_complete`（完整样本中空 Murcko scaffold 的比例），结合 SMILES 和 fingerprint diversity 评价多样性。

### 确认评估的独立任务分工

为减少单个耗时能量候选阻塞整个确认队列，核实 GPU39 作业31228048 的4CPU分配后，将17个已生成、未开始评估的确认/开发补充目录交给独立 CPU evaluator。目录名单保存在 `parallel_handoff_folders.txt`，不包含 GPU29 仍在运行的 `fk_i50_b5_b800_s2026`。仅对原父队列 PID1209957 使用 SIGSTOP，能量子进程 PID1261123 保持运行；独立批次结束或异常退出时通过 finally 恢复父队列。独立 evaluator 使用单线程 Vina 和单线程能量 ensemble，与最多两个生成进程合计不超过4CPU。评估数值协议不变，不增加候选或改变预算。进程标识是此会话诊断信息，不应在未来复跑时沿用。

生成矩阵结束后，GPU39 的4CPU资源用于更多独立评分。当前分层恢复关系为：level3 队列完成后恢复 level2，level2 完成后恢复 level1，level1 完成后恢复 GPU29 原队列。每次仅停止父队列，已有能量子进程继续执行；下层目录名单从上层剔除其正在评估的目录和已完成目录。恢复后的上层逐一跳过下层新增的 EVALUATED，避免同时写入同一目录。名单、日志和 `.resume.json` 保存于输出根目录。正式评估的 Vina 并行度可能不同，因此跨正式目录的原始耗时只作运行记录；统一硬件和 worker 设置的重复 prototype timing 用于成本结论。

### CPU 槽位自动接续

第四层父队列停止后，4槽位调度器接管 GPU39 四个仍在计算的能量子进程。记录每个 PID 的启动 tick 和候选目录，检查 PID 身份，不能仅凭日志或观察超时重启。子进程成为 zombie 且 exit_code=0 后，核查全部候选覆盖、SDF SHA256、50-conformer/threshold100/seed42/thread1 能量配置以及每个选择结果的计划分母，再补写 EVALUATED 和恢复证据。空闲槽位立即启动剩余目录的完整评估流水线，Vina workers=1，全部评估最多4个CPU槽位。调度器不改变候选、冻结采样或阈值；完成后恢复第四层父队列，逐级恢复原队列。调度器日志和状态保存于 `evaluation_scheduler*.json`，CPU 评估状态文件不计作 GPU generation ledger。

原 GPU29 能量子进程正常完成并复核640个候选后，释放的CPU用于第二个3槽位调度器（原有8CPU分配中为其他任务保留4CPU，再留1CPU余量）。它按反向目录顺序接续主调度器尚未开始的目录。新 evaluator 在整个目录评估期间持有 `tts_evaluation.lock`，竞争任务等待，获取锁后重新检查 EVALUATED 并复用完成结果。跨节点互斥探针在 GPU39 持锁、GPU29 非阻塞竞争的条件下通过，证据为 `smoke/cross_node_lock_probe.json`。GPU29 辅助调度器不独立恢复旧父队列；原恢复链由 GPU39 主调度器负责。

### FK 与独立候选池的原子数策略

逐一比较全部已生成 FK 任务与对应 seed 的独立候选池 `sample.yml`：`variable_mol_size` 参数完全相同，均为 pocket_atoms_based，mean=0.05924407×pocket atoms+0.1478300335619629，std=6.303689641435993，min=5。FK 不要求各粒子固定相同原子数，复制完整父图后重新构造 batch；输出保留实际原子数。初始先验一致不代表重采样后大小分布一致，后者仍需 size/QED/ligand-efficiency guardrail 与分层结果检查。证据为 `tables/atom_count_strategy_audit.json`。

## 原生 refinement 的严格实际 NFE 补充对照

原生链会提前停止，B400/B800 是调用上限而非每个输出的固定消耗。`tables/native_actual_nfe_matched_selections.csv` 对全部 100 口袋、5 seed、3 个预算的 1500 个原生输出，使用同 seed 原始 N8 池的前 N 个候选，其中 N=该原生输出的实测 graph-NFE/100。包含 N3/5/6/7 的诊断前缀，几何置信度选择规则保持冻结；每一对的实际 graph-NFE 完全相等，失败样本不删除。配对 CI 先在口袋内平均 seed，再 bootstrap 5000 次。

这一对照依赖先观察原生链实际消耗，是回顾性资源匹配诊断，不能当作可部署的预算分配策略，也不替代预声明 N1/2/4/8 主曲线。全 100 口袋的原生减对照 P_phys 差值在三个预算分别为 −13.0、−12.0、−10.0 个百分点，P_joint 为 −8.4、−9.2、−8.6 个百分点；各自 95% CI 均低于零。完整数值及开发/确认分层见 `native_actual_nfe_matched_comparisons.csv`。

## 完整核心曲线后的 N16 决策

全部核心矩阵完成后，几何置信度 Best-of-N 从 B400 到 B800 的 P_phys 配对差值 +1.4pp，95% CI [−1.4,+4.4]pp；P_joint +2.0pp，95% CI [−0.8,+4.8]pp。均未满足冻结的正下界条件，因此不追加 N16/B1600。此决定使用完整 100 口袋×5 seed，不根据确认适配的结果修改。已准备的扩展脚本保留用于复查，未运行、未消耗扩展 GPU 预算。

## 冻结粒子池的配对多样性与大小

`selected_pool_guardrails_per_pocket.csv` 使用所有冻结FK确认生成及独立P4/P8前缀，80口袋×5seed，候选化学validity/多样性不等待能量，亦不以能量可算性筛样。`selected_pool_guardrails_comparisons.csv` 先在口袋内平均seed，对80簇bootstrap5000。fingerprint diversity只在双方同一对均可定义时比较，395/400或400/400对及80口袋覆盖显式报告；主指标不因此删分母。B400粒子指纹多样性轻度下降约0.012；B800约0.0027，CI含零。粒子池重复率绝对水平低。B800池平均重原子数差+0.6566 [0.3403,0.9678]，不能由配置先验一致推出最终分布一致。候选池均值与最终排序输出均值是不同统计对象，报告分别列出。

FK P8的逻辑粒子总体包含8个图，但模型forward由`batched_forward(max_batch=4)`拆为两个四图调用；不能把粒子数当物理model batch。确认、两套计时及开发补齐的26个FK运行，run.json实际graph/forward计数比均为4，且batch_size=4，核验见 `tables/fk_physical_batch_audit.json`。中间reward/resampling在整个同口袋粒子总体上执行，其成本包括在运行墙钟中。
